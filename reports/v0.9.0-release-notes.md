# ts-chef v0.9.0 candidate release notes

Version 0.9.0 adds Quick Workbench for selecting one operation, editing parameters and exporting complete results. Small safe inputs preview automatically; changed parameters and expensive operations require explicit Run.

Binary results retain their original bytes and offer strict UTF-8, Hex and Base64 export. Preview truncation does not truncate exports. Selection replacement uses the original document, range, version and text snapshot; late results and stale clipboard reads are discarded.

All 15 catalog argument types are supported. AES now explicitly encodes Unicode input as UTF8 and validates decoded UTF8 output; Raw remains a byte-character format. Empty AES IVs follow the documented zero-IV default. Generate Lorem Ipsum has a numeric default. Triple-DES uses a portable ECB name and an existing Forge fallback for modes unavailable in VS Code/Electron.

Dependency updates address available runtime advisories. RSA Verify rejects malformed DigestAlgorithm elements without breaking canonical/omitted-NULL SHA signatures or legacy raw hash semantics. The remaining node-forge advisory is mitigated at the application's verification boundary, not hidden from npm audit.

The extension retains 479 operations across 72 lazy chunks. External Bzip2, Capstone, LZMA, jq and MD6 runtimes and WASM resources are now explicitly packaged. CI and release workflows require typechecking, unit tests, real VS Code host and webview tests, documentation and installed package validation.

Known limitations: explicitly run operations are not sandboxed for intermediate memory/CPU usage; manual outputs are checked after an operation returns. Platform coverage and remaining development-tool advisories are recorded in the release readiness report. Release approval depends on the mandatory platform CI and installed-package upgrade gates; see the release readiness report.


## Upgrade from 0.8.1

Install the 0.9.0 VSIX over the existing extension in the same VS Code profile and reload the window. The extension identifier remains `michaelweiss.vscode-ts-chef`; global/workspace variables, saved pipelines and settings retain their storage formats. Back up private recipes and variables before upgrading. Quick Workbench favorites persist, while its input, results and argument values are intentionally not restored after restart.

## Test infrastructure corrections

Linux CI explicitly opts into a test-only Electron sandbox exception for isolated downloaded VS Code instances. Normal extension use retains VS Code's sandbox. UI tests select a visible workbench and establish renderer/window focus before Command Palette input, including after cold restarts. Failure reports include process logs and window diagnostics; release publication rechecks the tested artifact hashes and tag commit.
