## Historical 0.8.1 fixture and upgrade limits

The official 0.8.1 archive has SHA-256 `2d1e6ddda1a1d69cf18202c2777811d07da953c7b09ef63a077f09c4b51ae12f`. ZIP inspection and real Linux CI proved that it omits the external runtime packages and fails activation in a pristine profile with `Cannot find module 'libbzip2-wasm'`.

The upgrade comparison retains that exact official archive. Only its baseline execution receives the omitted runtime packages in the disposable profile's normal Node module search path, outside the installed extension. The helper removes the fixture in a finally block **before candidate installation**. Regression tests verify resolution, removal on success/failure and absence for candidate resolution. The candidate also strips inherited `NODE_PATH`; it must use its own packaged runtimes. Both its independent fresh installation and the post-upgrade execution passed.

This proves the new package's standalone behavior, compatibility with functioning legacy behavior, preservation of existing data and recovery after installing 0.9.0. It does **not** claim that the defective, untouched 0.8.1 archive independently works in a pristine profile. The fixture and this limitation are also disclosed in the release notes.

## Security and residual risk

The tag workflow's fresh dependency audit reports **43 affected package records: 35 high, 8 moderate, 0 critical**. Production contains **one high**, node-forge 1.4.0, and no critical. These are package records, not counts of distinct exploitable application defects.

The vulnerable Forge library and permissive verifier implementation remain bundled. The reviewed RSA Verify path uses native PKCS#1 padding validation and a length-checked constant-time comparison of the complete expected DER DigestInfo. **20 focused tests** cover legitimate encodings, omitted-NULL SHA compatibility, changed signatures/messages, extra elements, wrong OIDs, wrong digest lengths, invalid parameters and trailing bytes. No additional direct application call to the affected Forge verifier was found. The [upstream advisory](https://github.com/advisories/GHSA-86w9-cpqp-85rv) still lists no patched version.

The release accepts this documented, bounded application-level mitigation; it does not declare the entire dependency safe or claim exhaustive transitive reachability analysis. New verification consumers require review. Development advisories and an upstream Forge update remain maintenance work. Explicit operations can consume intermediate CPU/memory before final-output limits apply. Details: [security assessment](v0.9.0-stabilization-security.md) and [product security model](../docs/privacy-security.md).
