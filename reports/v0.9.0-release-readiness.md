## Failure analysis and corrections

The original [CI run 38625542848](https://github.com/MichaelWeissDEV/ts-chef/actions/runs/38625542848) was read through GitHub's job/log APIs. Ubuntu failed before extension activation with the SUID sandbox ownership/mode error and SIGTRAP. Both launchers now share fixed VS Code version validation, disposable user/extension directories, environment sanitation, timeouts and launch arguments. Only Linux with explicit `TSCHEF_TEST_NO_SANDBOX=1` receives `--no-sandbox`. CI supplies the flag for Linux host/UI and the complete packaging gate, so installed VSIX/upgrade subprocesses inherit it. CLI installation receives only isolation arguments, never Electron sandbox arguments. There are no OS permission changes or product sandbox changes. Linux runner user-namespace behavior has not been re-probed locally; an actual Ubuntu run remains necessary.

UI launch/restart now selects a visible `.monaco-workbench` from current windows, brings that page forward, focuses its corresponding Electron BrowserWindow, clicks a neutral status-bar area and checks renderer focus before keyboard use. The Command Palette must be visible/editable and contain exactly the requested command label. One retry is permitted only when renderer focus was demonstrably lost. No command execution retry or timeout increase was added. Historical logs prove the hidden-input symptom but do not identify which OS/window took focus; that narrower root cause cannot honestly be reconstructed from those logs.

Restart checks preserve favorite persistence and verify empty input/result plus disabled Copy, Replace and New Document after restored windows/themes, successful execution, invalid parameters, changed favorites and large private input. Real clicks/keyboard/webview assertions remain; host `handleMessage` checks are separate.

Diagnostics use `reports/test-results/<platform>/<host-or-ui>/<mode>/<run>/`. JSON summaries include platform, architecture, versions, timestamp, phase, status and actual check counts. Host failures retain sanitized process/VS Code logs, exit code/signal and extension-start evidence. UI failures retain window identities, renderer focus, frame count, dialogs, palette state, screenshots and Electron/renderer logs. Shared launch and cleanup diagnostics received subsequent static edits after the earlier UI runs and have not been re-executed in VS Code following the user's prohibition.

## Security

Fresh registry audit: **43 affected package records: 35 high, 8 moderate, 0 critical**; production **1 high, 0 critical**. These are package-level records, not counts of distinct exploitable application bugs. The audit gate passed its explicit mitigation policy; the findings were not suppressed.

node-forge 1.4.0 remains installed and bundled, including vulnerable verification implementation code. [GHSA-86w9-cpqp-85rv](https://github.com/advisories/GHSA-86w9-cpqp-85rv) still lists no patched release. RSA Verify checks native PKCS#1 padding and the complete expected DER DigestInfo. **20 focused tests pass**, including legitimate formats and canonical/omitted-NULL SHA, modified signatures/messages, nested/outer extra elements, wrong OIDs and digest lengths, invalid parameters and trailing bytes. No additional direct application Forge verifier call was found. This is a bounded application-path assessment, not a transitive whole-library guarantee.

Recommendation: retain the documented application mitigation and accept that bounded residual risk for the reviewed path; keep upstream monitoring and development-tool upgrades as follow-up. Overall release approval remains FAIL for missing mandatory evidence. See `v0.9.0-stabilization-security.md` for detail. Manual operations remain subject to intermediate CPU/memory risk; output limits are not an operation sandbox.
