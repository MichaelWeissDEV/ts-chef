### node-forge

- Severity: high; affected range: `*`.
- Installed baseline paths/versions: `node_modules/node-forge@1.4.0`.
- Current paths/versions: `node_modules/node-forge@1.4.0`.
- Scope: production, lazily loaded operation/runtime code; current bundled source-map evidence: **present**. VSIX stores bundled modules in dist chunks, rather than shipping every root dependency directory.
- Reachability and recommendation: RSAVerify was the sole repository-owned forge publicKey.verify call. Replaced by native PKCS#1 padding decoding and complete expected DigestInfo comparison. Extra NULL/SEQUENCE/OCTET children and wrong digest OIDs fail; canonical and omitted-NULL SHA identifiers pass. Forge hashing/PEM parsing remain for compatibility. No other src forge verification sink was found. The vulnerable library code remains bundled but the examined application verification route no longer invokes it.
- Available npm fix: false. No fixed upstream release reported. Keep the narrow verified application mitigation and re-audit when upstream ships a fix.
- Advisories: [node-forge RSA PKCS#1 v1.5 signature verification accepts extra nested DigestAlgorithm elements](https://github.com/advisories/GHSA-86w9-cpqp-85rv) (`<=1.4.0`).

## All flagged baseline packages, including development tools

Development dependencies are excluded from the VSIX unless explicitly identified by a source map. Jest, ESLint, VSCE and documentation/build tools execute during local/CI builds only. Remaining braces findings concern deeply nested glob patterns; these tools receive repository-controlled fixed patterns, not extension-user input. Building attacker-controlled source already permits build-script execution in the same trust context; CI uses read-only tokens except the tag-only final publication job. No blanket claim of immunity for arbitrary unreviewed repositories is made.

The retained esbuild moderate advisory concerns its development HTTP server. This project uses esbuild bundle/watch commands and does not start that server. concat-md is not referenced by an npm script; legacy tooling remains a future cleanup item. No major Jest/VSCE migration was forced merely to change audit totals.
