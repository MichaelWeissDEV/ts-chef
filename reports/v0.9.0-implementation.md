## Known Issues and Limitations

1. **Quick Workbench Input Tracking:** The current implementation tracks input text via message passing, but real-time input changes are only captured on `change` event (not `input`). This means rapid typing might not be captured until the field loses focus.

2. **Argument Support:** The Quick Workbench currently executes operations with empty arguments (`[]`). Operations requiring arguments will use their default values or fail.

3. **Preview Safety:** The `isSafeForPreview` function uses a placeholder implementation with a hardcoded list of unsafe operations. A proper implementation should use `src/panels/pipelineLivePolicy.ts`.

4. **State Persistence:** Favorites and recents are only stored in memory and reset when the panel is closed. They should be persisted using VS Code's extension state.

5. **Selection Replacement:** The replace functionality creates a new snapshot but doesn't properly verify if the original selection is still valid. This could lead to replacing wrong text if the user changes the selection between loading and replacing.

6. **Large Result Handling:** Results are truncated at 100,000 characters but the truncation message might not be immediately visible to users.

7. **Error Handling:** Some error cases might not provide the most user-friendly messages.
