# v0.9.0 stabilization security assessment

Date: 2026-10-15. Scope: dependency audit and the application's RSA verification boundary; no repository-wide security scan is claimed.

## Current dependency results

Fresh `npm run audit:dependencies`: PASS under the documented application mitigation policy. All dependencies: 43 package records, 35 high, 8 moderate, zero critical. Production: one high, zero critical. The audit wrapper fails on incomplete registry responses and unreviewed high/critical production findings. Development advisories remain visible and require a separately tested tooling update.

## GHSA-86w9-cpqp-85rv

The [GitHub reviewed advisory](https://github.com/advisories/GHSA-86w9-cpqp-85rv), checked on the assessment date, affects node-forge through 1.4.0 and lists no patched version. It concerns extra nested DigestAlgorithm elements accepted by the PKCS#1 v1.5 verifier, with low-exponent keys enabling forgery.

- Vulnerable library installed: **yes**, node-forge 1.4.0.
- Vulnerable implementation included in bundled VSIX chunks: **yes**. Forge's CommonJS aggregate remains needed by multiple operations.
- Additional direct application calls to the affected verifier: **none found**. Search covered `src/**/*.ts` for Forge imports, `.verify`, `verifyCertificateChain` and `verifySignature`. JWT Verify uses jsonwebtoken, ECDSA Verify uses jsrsasign, GOST Verify uses its GOST implementation and Protobuf's verify validates message structure. Other Forge callers use key parsing, signing, encryption, hashes, symmetric modes or random generation.
- Boundary: attacker-supplied signature, public key, message, format and digest choice enter `RSAVerify.run`. Native `publicDecrypt` checks PKCS#1 type-1 padding, then a constant-time comparison checks the complete canonical DER DigestInfo, including its length. SHA identifiers may omit NULL for compatibility; MD5 may not.
- Focused tests: **20 passed**. Canonical digest signatures, PKCS#1/SPKI public keys, Raw/Hex/Base64 messages, changed message/signature, extra nested and outer elements, wrong OID, short/long digest, non-NULL parameter, trailing bytes, omitted-NULL SHA and legacy raw Unicode semantics are covered.
- Required Forge usage remains for existing PEM parsing, raw hashing semantics and other operations; replacing it broadly is outside stabilization scope.

Recommendation: accept the bounded application-level mitigation for the reviewed RSA operation, retain the advisory in audits and track an upstream fix. This does not declare all Forge code safe or claim an exhaustive transitive reachability proof. New consumers of RSA/certificate verification require fresh review. Overall release approval remains blocked on final-commit CI and final-package installation/upgrade evidence.

Explicit manual operations can still allocate memory or consume CPU before final-output limits run. The Linux sandbox exception is a separate, explicit test-harness policy and never changes the installed product's launch behavior.
